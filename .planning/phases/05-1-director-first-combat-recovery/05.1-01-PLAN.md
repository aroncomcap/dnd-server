# Plan 05.1-01: Target Authority, Recovery, And Optional Combat Compression

## Goal

Restore the solo-DM feel by preserving story momentum outside deliberate fights, requiring valid targets before combat resolution, and adding table recovery tools for stuck scenes.

## Work Breakdown

1. Add shared target authority helpers for default attack/support targets and action target validation.
2. Route action-parser combat defaults through target preferences instead of first nearby enemy text.
3. Make the combat engine fail closed with `target_required` results before dice rolls, turn advancement, or spell-slot spending.
4. Add a deterministic combat fast path so parseable tactical actions resolve without a narration LLM call.
5. Persist per-player attack/support target preferences and include them in combat socket payloads.
6. Add compact combat UI controls for attack target, support target, and optional `Finish Cinematically`.
7. Replace host reset UX with `Move to Next Beat`, clearing ephemeral combat/scene state and asking the DM to advance the main story beat.
8. Add focused tests for parser preferences, target validation, fast-path tactical output, UI contracts, and recovery/cinematic socket contracts.

## Verification

- `node --test --test-concurrency=1 tests/action-parser.test.js tests/combat-engine.test.js tests/game-ui-regression.test.js`
- `npm test` if focused tests pass.
- `git diff --check`

## Success Criteria

- Ambiguous target-required actions pause for a valid target instead of resolving against `None`, `with`, a living enemy for Revivify, or another placeholder.
- Parseable tactical combat actions emit deterministic tactical results without a model call.
- Player target preferences remain stable until changed and are used by parser defaults.
- `Move to Next Beat` preserves characters/history while ending active combat and clearing transient state.
- `Finish Cinematically` is visible during combat and does not replace round-by-round play as the default.
