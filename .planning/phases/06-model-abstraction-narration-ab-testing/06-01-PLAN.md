# Plan 06-01: Model Abstraction And Narration A/B Testing

## Goal

Replace production Claude/Anthropic runtime calls with a provider-agnostic Tavern `llm` layer backed by AI SDK Core, then add sticky player-visible narration A/B testing with telemetry, retention cleanup, and an output-quality harness.

## Locked Decisions

- Use Tavern-owned `llm` methods as the product boundary.
- Use AI SDK Core under the adapter for provider/model registry support.
- Use OpenAI as first production provider.
- Initial narration experiment: `openai:gpt-5.4-mini` at 70% vs `openai:gpt-5.4` at 30%.
- Store full prompt/output text during active evaluation, then delete raw text periodically while retaining hashes/metadata.
- Show subtle optional feedback controls after completed narrations.
- Commit, push, deploy, and validate unattended after tests pass.

## Work Breakdown

1. Add dependencies and `llm/` modules:
   - provider registry,
   - model registry and cost estimation,
   - streaming/text/object completion facade,
   - sticky experiment assignment,
   - telemetry and retention cleanup helpers,
   - schemas.

2. Add database support:
   - `llm_experiments`,
   - `llm_experiment_assignments`,
   - `llm_runs`,
   - `narration_feedback`,
   - cleanup and reporting queries.

3. Migrate runtime AI calls:
   - `narration-pipeline.js` streaming narration, extraction, validation,
   - legacy narration and options fallback in `server.js`,
   - story summary, OOC, catch-up, party generation, enemy tactics, monster persona generation,
   - `action-parser.js` and `stat-parser.js` AI helpers.

4. Add player feedback:
   - completed DM messages carry `llmRunId` where available,
   - feedback endpoint/socket event records rating/tags/note,
   - subtle message-level UI controls in `public/game.html`.

5. Add admin/reporting:
   - JSON endpoint for model-lab summary,
   - admin table or compact panel using rating, tags, cost, latency, failures.

6. Add output harness:
   - mocked-provider fixture checks in CI,
   - optional live model run mode,
   - assertions for marker leakage, options, verbosity, engine-owned mechanics, structured schema, telemetry.

7. Validate and ship:
   - focused unit tests,
   - full `npm test`,
   - Playwright campaign smoke where practical,
   - commit, push, deploy, Railway status/log check, production smoke.

## Verification Gates

- No direct `@anthropic-ai/sdk` production runtime dependency remains.
- `rg "anthropic|claude"` in source only finds historical docs, comments, or intentionally retained migration references.
- Unit tests pass.
- Output harness passes in mocked mode.
- Production deploy succeeds and live smoke reaches completed narration with usable actions.
